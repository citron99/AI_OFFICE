# Защита повторной отправки задач

`POST /api/v1/tasks` принимает необязательный заголовок `Idempotency-Key`:
1–128 символов латиницы, цифр, `_` или `-`. Клиент генерирует случайный ключ
для новой отправки и сохраняет его при сетевых повторах этой отправки.

- Один владелец + один ключ + одинаковый нормализованный запрос возвращают
  тот же task_id с текущим состоянием (HTTP 201), без повторного запуска.
- Изменение тела с тем же ключом возвращает 409 `IDEMPOTENCY_CONFLICT`.
- У разных владельцев одинаковые ключи независимы. Без заголовка каждая
  отправка создаёт новую задачу, как раньше.
- Ключ хранится до удаления записи задачи, автоматического TTL нет.
- После failed/cancelled повтор возвращает прежнюю задачу. Явный `/retry`
  создаёт новую задачу без унаследованного ключа и с новым согласованием.
- Уточнение задачи не меняет отпечаток исходного запроса.

Уникальное ограничение PostgreSQL защищает от одновременных отправок;
только создавший запись запрос запускает анализ или публикацию в очередь.
Повтор может получить queued, пока первый запрос ещё выполняется: дальше
нужно опрашивать GET задачи. Это не гарантия exactly-once доставки Celery;
за повторную доставку отвечают существующие блокировки worker.

Для сравнения хранится SHA-256 канонического валидированного тела, а не
дополнительная копия исходного текста. Сами ключи не должны содержать секреты.
Веб-интерфейс отправляет ключ автоматически и удерживает его вместе с исходным
телом и ID загруженного вложения в памяти вкладки. Двойное нажатие игнорируется;
после ошибки можно повторить тот же запрос. После успешного создания повтор
также возвращает прежнюю задачу. «Новая задача» явно сбрасывает ключ и разблокирует
поля; при неизвестном результате показывается предупреждение о возможном дубликате.

Перезагрузка/закрытие вкладки или смена доступа сбрасывают локальный ключ.
Перед новой отправкой после перезагрузки проверьте список задач. Секреты и тексты
не записываются в localStorage/sessionStorage. Если потерян ответ загрузки файла,
повтор может оставить лишнее вложение, но запрос создания задачи до успешного
получения ID вложения не отправляется. Уточнение юридической задачи и регистрация
источника используют независимые поля и не меняют сохранённую отправку.
