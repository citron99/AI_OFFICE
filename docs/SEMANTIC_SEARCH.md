# Локальные семантические эмбеддинги: пилотный адаптер

По умолчанию сохраняется mock-поиск. Адаптер Sentence Transformers опционален.
Настоящая мультиязычная MiniLM проверена на CPU в Linux-контейнере без сети.
Дополнительный стек зафиксирован в requirements-semantic.lock; основной uv.lock не менялся.
Проверка качества нового набора не пройдена: recall вырос, но остаются ложные результаты.
Запуск и измерения: [SEMANTIC_EVAL.md](SEMANTIC_EVAL.md).

## Подключение

1. Подготовить доверенную локальную модель Sentence Transformers, не меняющую файлы во время работы.
   Поддерживается симметричное текстовое encode; модели с разными query/document prompts
   или remote code требуют отдельного адаптера. Не загружать случайные модели как доверенный код.
2. Для Linux x86_64 / Python 3.12 использовать Dockerfile.semantic либо установить
   `uv pip install --torch-backend cpu --require-hashes -r requirements-semantic.lock`
   поверх окружения основного lock. Другие платформы требуют отдельной проверки.
   Обычный uv sync может удалить дополнительные пакеты; выделить окружение для испытаний.
3. Применить миграции до 0005: `uv run alembic upgrade head`, затем установить:

```dotenv
EMBEDDING_PROVIDER=local_sentence_transformer
EMBEDDING_MODEL_PATH=C:/models/approved-model-snapshot
EMBEDDING_DIMENSIONS=384
SEMANTIC_MIN_SCORE=0.3
```

Размерность должна совпадать с моделью; усечения векторов нет. Порог 0.3 — стартовый параметр,
не калиброванная юридическая релевантность. С дополнительными пакетами запускать
`uv run --no-sync uvicorn app.main:app --host 127.0.0.1`.

Адаптер загружает существующий локальный каталог, использует CPU,
`local_files_only=True`, `trust_remote_code=False`. Файлы модели хешируются при запуске:
ID содержит SHA-256 снимка, а не имя каталога. Модель загружается один раз на приложение.
Это не sandbox; нужны доверенные неизменяемые файлы. При индексации структурные фрагменты
дополнительно делятся по фактическому tokenizer с учётом специальных токенов.
Части сохраняют исходные символы: нет decode, перефразирования или молчаливого truncation.
Каждая часть повторно проверяется, предпочтение отдаётся пробелу рядом с серединой.
Для строки без пробелов допускается граница между символами. Это не лингвистический
sentence splitter: связь между соседними частями может потеряться, overlap пока нет.
Исходные page/article сохраняются; locator получает суффикс token part N.
Общий лимит 2000 чанков применяется после деления, до embedding и публикации источника.
Прямой вызов embed по-прежнему отклоняет слишком длинный текст.

LawyerAgent заранее делит вопрос и фрагменты вложений на подходящие поисковые окна.
Не более 64 окон суммарно: превышение даёт явную ошибку до первого поиска, без частичного обзора.
Полный извлечённый текст вложений остаётся в контексте LLM. Отдельный search API не объединяет
автоматически длинные запросы: при превышении token limit требуется более короткий запрос.

Схема разбиения версионирована новым namespace `st-local-v2:<SHA256>`.
Даже для того же снимка v1 и v2 изолированы: переиндексируйте старый source_id через reindex.
Старая версия не удаляется. При отсутствии источников v2 поиск не возвращается к v1.
Mock namespace и его разбиение источников остаются прежними.

Официальный контракт конструктора/encode:
[Sentence Transformers](https://www.sbert.net/docs/package_reference/sentence_transformer/model.html).

## Переиндексация без удаления старых цитат

`POST /api/v1/knowledge/sources/{source_id}/reindex` создаёт новую копию источника
для активной модели, сохраняя паспорт и повторно проверяя SHA-256 файла.
Старый источник и его чанки остаются неизменными. Ответ содержит новый source_id,
embedding_model и embedding_dimensions. Если передан источник уже текущей модели,
возвращается его прежний ID. Повторный запрос к старому ID возвращает уже созданную копию.
Ответ содержит `reindex_of_id` — исходный ID. Уникальный индекс БД защищает сочетание
исходного ID, модели и размерности; при конфликте вставки API возвращает победивший результат.
Чанки публикуются в одной транзакции с источником, поэтому частичный индекс не возвращается.
Переиндексация цепочки A → B → C и отдельно A → C имеет разные исходные ID и может создать
два результата модели C; это идемпотентность конкретного запроса, не глобальная дедупликация.
Фоновая массовая переиндексация пока не реализована.

Миграция 0005 не угадывает происхождение старых копий: их reindex_of_id остаётся NULL.
Первый запрос после обновления для исторического исходника может создать новую связанную копию.
При downgrade удаляется только поле происхождения и ограничение уникальности; источники и
чанки сохраняются. Связь происхождения проверяется сервисом, а не внешним ключом.
Поле нельзя задать через публичный SourceCreate. Удаление источников отдельным API не поддержано.

Поиск фильтрует модель и размерность, кроме прежних ACL/даты/юрисдикции.
Если для новой модели ничего не проиндексировано, возвращается пустая выдача, без fallback
на несовместимые векторы. У семантической модели нет фильтра обязательных общих слов.
Mock-поиск сохраняет lexical-фильтр. SearchResponse сообщает модель, размерность,
версию retrieval и предупреждения; LawyerAgent сохраняет фактическую версию retrieval.

Миграция расширяет pgvector колонку до vector без фиксированной размерности, сохраняя данные.
CASE защищает вычисление расстояния от строк другой размерности независимо от порядка SQL-фильтров.
Downgrade запрещён, если есть источники не с 128 измерениями. Не удаляйте их ради downgrade
без отдельного решения о миграции данных. На PostgreSQL 16 с pgvector проверены сохранение
старых векторов при миграциях, смешанные размерности и конкурентная переиндексация;
инструкции: [POSTGRES_TESTING.md](POSTGRES_TESTING.md).

Векторы проверяются на размерность, NaN/Infinity, нулевую длину и нормализуются.
Ошибка генерации не публикует частичный источник. Лимит 5000 кандидатов остаётся.

## Что остаётся непроверенным

Подставной semantic provider проверяет API/поиск/переиндексацию; реальная MiniLM дополнительно
проверена на небольшом синтетическом наборе. Нужны независимая оценка специалистами,
калибровка порога на отдельном наборе, оценка влияния новых границ чанков
и измерение ресурсов под нагрузкой.
eval_retrieval.py по умолчанию выполняет прежнюю mock-регрессию; параметры --suite и
--model-path включают отдельную оценку настоящей локальной модели.
