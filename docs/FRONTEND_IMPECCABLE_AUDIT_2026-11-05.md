# Frontend audit по методике Impeccable

Дата: 2026-11-05. Объект: текущий рабочий каталог frontend, включая незакоммиченные изменения. Режим поверхности: Operate.

## Последующие исправления

Первый отдельный шаг: исправлен пункт 3 (недоступные данные как низкий риск).
Дашборд различает loading/error/ready/refreshing/stale, маскирует незагруженные KPI,
показывает время предыдущего снимка после сбоя и не оценивает риск без финансового отчёта.
Отсутствие отчёта больше не объявляется отсутствием просроченной задолженности.
Ответы загрузки от предыдущего токена не применяются к новому контексту доступа.
Числовая формула riskSnapshot не изменена.

Проверки шага: 25 frontend-тестов и production build успешны; render-smoke расширен
проверками loading/error/no-report/loaded-zero/refreshing/stale. Локальный Edge с
тестовыми ответами API прошёл цикл initial failure → loaded KPI → refresh failure
(предыдущий снимок сохранён) → recovery. Снимок результата:
`.hallmark/dashboard-no-data-fixed.png`. Остальные пункты аудита этим шагом не закрыты;
исходная оценка ниже оставлена для сравнения, повторная итоговая оценка ещё не выполнялась.

## Вердикт implementation integrity

**Fail: визуальная система пока несогласованна.** Подтверждены конфликты общего CSS с feature-компонентами, неполное покрытие тёмной темы, дубли заголовков и смешение отсутствующих данных с нулевыми показателями. Предыдущий polish частично улучшил подписи, но не завершил унификацию стилей. Повторяющиеся заголовки появились в его незакоммиченном diff.

Это технический аудит, не подсчёт эстетических запретов Hallmark. Чистый белый фон, системный шрифт, тире и произвольные отступы сами по себе не считаются ошибками.

## Объём и воспроизводимость

- Просмотрены React/CSS, API client, тесты, конфигурация Vite и сценарий render-smoke.
- Текущие исходники запущены временным Vite на loopback. Контейнерный frontend на 8081 недоступен.
- Playwright с установленным Microsoft Edge, headless: проверена навигация по всем 10 разделам при 1440×900 и 375×900. Неперехваченных pageerror нет. Это проверка пустых/недоступных состояний, серверная часть не запущена.
- Дашборд снят в светлой и тёмной теме на обеих ширинах. Контраст вычислен из CSS-цветов, измеренных через getComputedStyle. Измерения относятся к непрозрачным фонам и известному фону предков.
- Проверен Shift+Tab в палитре команд.
- `npm test`: 25/25; `npm run build`: успешно; `node scripts/render-smoke.mjs`: SMOKE OK.
- Автоматический detector Impeccable **не выполнен**: launcher не смог установить/закешировать движок 0.1.18, включая повтор с необходимым доступом. Найденное ниже проверено кодом и независимыми браузерными измерениями.
- Не проверены: авторизованные серверные сценарии, заполненные таблицы в браузере, реальный touch, физические устройства, screen reader, zoom 200–400%, Core Web Vitals на реальной сети. SSR smoke охватывает несколько feature-компонентов с фикстурами, но не заменяет эти проверки.
- PRODUCT.md и DESIGN.md в проекте не найдены.

## Подтверждённые проблемы

### 1. [P1] Контраст тёмной темы не соответствует WCAG AA

Категория: Accessibility / Theming. Стандарт: WCAG 1.4.3 (Contrast Minimum).

Места: `frontend/src/design.css:73`, `:201`, `:203`; `frontend/src/styles/tokens.css:67`, `:113`.

Подтверждённые пары:

| Элемент | Текст / фон | Контраст |
| --- | --- | --- |
| `.ops-empty` | #94a3b8 / #f9fbfd | 2,47:1 |
| `.ops-progress strong` | #203653 / #0b0f19 | 1,56:1 |
| `label` в рабочем столе | #454d58 / #0b0f19 | тёмный текст на тёмной карточке, ниже 4,5:1 |
| `button.primary` | #ffffff / #e8703f | 3,08:1 |

Пользователь не может уверенно читать подсказки, значения и подписи полей. `.ops-empty` сохраняет светлый hard-coded фон при смене цвета текста на светлый. Белый текст primary-кнопки слишком светлый для оранжевого фона.

Исправление: применять семантические surface/text/status токены ко всем указанным элементам, подобрать контрастный accent-ink, проверить обе темы и состояния hover/disabled. Существующий `designTokens.test.js:16` проверяет только пары из design.css, а не вычисленные стили и тёмную тему.

Команда: `/impeccable colorize`, затем `/impeccable harden`.

### 2. [P1] Палитра объявлена модальной, но фокус уходит на фон

Категория: Accessibility. Место: `frontend/src/CommandPalette.jsx:17–22`. Стандарт/паттерн: WAI-ARIA modal dialog, WCAG 2.4.3 и 4.1.2 требуют отдельной проверки после исправления.

Воспроизведение: открыть палитру, нажать Shift+Tab из поискового поля. В браузере фокус оказался на фоновой кнопке «Сформировать отчёт», `closest('.command-palette') === null`. Фон не inert. В эффекте нет восстановления фокуса на trigger. Глобальный Enter вызывает выбранную команду даже при переходе фокуса к другой кнопке; у input нет отдельной доступной подписи и связи с активным результатом.

Влияние: клавиатурный пользователь может взаимодействовать с закрытым диалогом фоном; озвучиваемое состояние не соответствует фактическому поведению.

Исправление: использовать уже имеющийся native dialog-подход из DecisionDialog, либо реализовать полное удержание/возврат фокуса и inert-фон; согласовать Enter с текущим фокусом; связать поиск с результатами.

Команда: `/impeccable harden`.

### 3. [P1] Недоступные данные представлены как низкий риск

Категория: Implementation Integrity. Места: `frontend/src/main.jsx:129–135`, `frontend/src/features/dashboard/Dashboard.jsx:8–18`, `:33–44`; `frontend/src/features/dashboard/NonPaymentRisks.jsx:37`.

При недоступном API видна ошибка сервера, но одновременно дашборд показывает «Низкий риск», 0/100, нули в KPI, «сохранённые данные» и «Просроченной дебиторской задолженности нет». Последняя фраза выводится также при `report === null`.

Влияние: собственник может принять отсутствие загруженных сведений за подтверждение отсутствия проблем. Текущие проверки корректности арифметики пустого riskSnapshot не подтверждают корректность этой UX-интерпретации.

Исправление: явно различать loading/error/no-report/loaded-zero; показывать «Нет данных для оценки», не выдавать low risk и отсутствие задолженности до успешной загрузки необходимых источников. Показывать свежесть уже загруженного снимка при ошибке обновления.

Команда: `/impeccable harden`, затем `/impeccable clarify`.

### 4. [P2] Дашборд создаёт горизонтальное переполнение на mobile

Категория: Responsive. Места: `frontend/src/design.css:169–181`, `:223`, `frontend/src/features/dashboard/Dashboard.jsx:20–28`.

При viewport 375 px `document.documentElement.scrollWidth === 388`. На снимке hero и следующие блоки выходят за правую границу основного контента. Остальные девять разделов в проверенном пустом состоянии имеют ширину 375 px.

Исправление: проверить intrinsic sizing grid/flex потомков дашборда, применить min-width:0 и переносы к нужным элементам. Не маскировать переполнение глобальным hidden. Повторить на 320/375/768 px и с длинными данными. Горизонтальная прокрутка nav-strip допустима сама по себе и не включена в дефект.

Команда: `/impeccable adapt`.

### 5. [P2] Общий header-селектор ломает композицию блока «Операционный контур»

Категория: Implementation Integrity / Responsive. Места: `frontend/src/design.css:44`, `:169–171`; `frontend/src/features/dashboard/Dashboard.jsx:21–23`.

`header > div { display:flex; align-items:center }` действует и на `.ops-hero > div`. Браузер подтвердил flex-direction:row. Заголовок, «Режим чтения» и описание становятся соседними колонками; на телефоне описание сжато до нескольких символов в строке. Это видно в обоих темах и не решается breakpoint внешнего hero.

Исправление: ограничить глобальное правило конкретной навигацией, для содержимого hero задать явную вертикальную композицию. Проверить аналогичные общие `aside`, `header` и `footer` в feature-модулях.

Команда: `/impeccable layout`.

### 6. [P2] Один раздел дважды объявляет почти одинаковый заголовок

Категория: Implementation Integrity. Места: `frontend/src/features/dashboard/DailyOwnerDigest.jsx:32–33`, `:42–43`; `frontend/src/features/dashboard/NonPaymentRisks.jsx:33–34`.

Видимые пары: «Ежедневная сводка владельца» + «Ежедневная сводка», «Основные риски неплатежей» + «Топ рисков неплатежа». Это подтверждено исходниками и снимками. Замена прежнего eyebrow на h3 оставила исходный h3.

Влияние: лишняя визуальная ступень, дубли в навигации screen reader и расход мобильного пространства.

Исправление: оставить один предметный заголовок, дату оставить метаданными. Факты и финансовый контекст сохранить.

Команда: `/impeccable distill`.

### 7. [P2] Polling может создавать пересекающиеся загрузки и молча оставлять устаревший UI

Категория: Performance / Implementation Integrity. Место: `frontend/src/main.jsx:129–135`, `:178–184`.

При активной задаче каждые 2500 ms вызывается refresh из девяти запросов и иногда десятый запрос выбранной задачи. Нет in-flight guard/AbortController на этот polling; обе ошибки подавляются пустым catch. Если сервер отвечает медленнее интервала, возможны параллельные циклы и поздняя запись старого ответа. Promise.all также откладывает обновление всех разделов при отказе одного источника.

Это подтверждённая структура кода и условный сценарий медленного сервера; реальная нагрузка и race в браузере без API не измерялись.

Исправление: следующий цикл после завершения текущего, отмена при смене пользователя/экрана, защита от устаревших ответов, явный индикатор ошибки/свежести. Разделить обновление независимых данных там, где это допускает контракт.

Команда: `/impeccable optimize`, затем `/impeccable harden`.

## Системные причины и исключённые ложные срабатывания

- Активны и tokens.css, и design.css, в обоих есть токены и компонентные правила. Импорты в main.jsx:3–4 ставят design.css после tokens.css. Порядок важен, но не объясняет все дефекты: более специфичные dark-правила работают, проблема также в непокрытых селекторах и буквальных значениях.
- `.ops-mini-grid b` фактически имеет тёмный фон родителя #111827; первоначальное подозрение о светлом фоне этого конкретного блока не подтвердилось и не включено в findings.
- `style.css` не импортируется текущим entrypoint. Его старые цвета не считаются дефектами отображаемого UI.
- Высота navbar-кнопок 32 px подтверждена; это ниже рекомендуемых 44 px для touch, но не автоматическое нарушение WCAG 2.5.8 AA (24 px и исключения). Отдельным P1 не считается.
- Наличие CSS `transition: transform` у meter не доказывает анимацию: компонент меняет width, а не transform. Layout-анимация после последнего polish не подтверждена.

## Что работает

- Доступны focus-visible, skip-link, labels основных форм, role=alert/status и reduced-motion.
- DecisionDialog использует native showModal и возвращает фокус на trigger; этот паттерн можно переиспользовать.
- Шесть feature views загружаются через React.lazy. Основной JS около 269 kB / 81,6 kB gzip, CSS около 46 kB / 9,9 kB gzip; оснований требовать тяжёлую оптимизацию bundle не найдено.
- Нет неперехваченных ошибок при переключении десяти разделов в проверенных состояниях. Тесты и SSR smoke проходят без изменения golden values.
- Отдельные финансовые empty states прямо говорят, что отчёт ещё не сформирован; этот подход нужно распространить на риск и сводные KPI.

## Приоритет исправлений

1. `/impeccable harden`: корректные состояния отсутствующих данных и модальность палитры.
2. `/impeccable colorize`: контраст обеих тем и полноценные семантические токены.
3. `/impeccable adapt` и `/impeccable layout`: переполнение дашборда и область действия header CSS.
4. `/impeccable distill`: дубли заголовков; `/impeccable optimize`: управляемый polling.
5. `/impeccable polish`: заключительный проход, затем повторить `/impeccable audit`.
