# Руководство пользователя (D-10)

Для собственника и сотрудников. Обучающая сессия проводится на этой инструкции.

## 1. Вход

- **Демо-режим** (`AUTH_MODE=demo`): ключ не требуется, вы — владелец demo-компании.
  Только синтетические данные.
- **Ключ доступа** (`AUTH_MODE=api_key`): введите ключ в Navbar (форма идентичности).
  Роль и компания назначены сервером вместе с ключом.
- **Токен-режим** (`AUTH_MODE=token`): приложите выданный access-токен; refresh-токен
  обновляет его автоматически через `/api/v1/auth/refresh` (TTL 15 минут).
- **OIDC** (`AUTH_MODE=oidc` + `/auth/oidc/session`): вход через корпоративный IdP;
  роль и компания приходят из утверждённого маппинга клеймов.

## 2. Дашборд

- **Ежедневная сводка** — принятый результат процесса «Ежедневный контроль денег»:
  watermark 1С, доступные деньги, приток/отток, aging дебиторки, топ рисков
  неплатежей с рекомендуемыми действиями, счётчик аномалий. Если сводки нет —
  процесс ещё не запускался.
- **Финансовые KPI** — из последнего расчётного отчёта (раздел «Бухгалтерия»).
- **Топ рисков неплатежа** — факты из отчёта, не прогноз.
- Метрики агентов и стоимость — ниже бизнес-блока; решения по ним не принимаются.

## 3. Рабочие сценарии

1. **Задача** — «Рабочий стол»: введите текст; система классифицирует (бухгалтерия /
   право / безопасность / смешанная), исполняет граф и возвращает результат с
   доказательствами и решением Policy Gate.
2. **Юридический вопрос** — укажите юрисдикцию и дату. Обязателен поиск в
   КонсультантПлюс; если источник недоступен — `WAITING_SOURCE`, финального вывода
   не будет. Это защищённая остановка, а не ошибка.
3. **Согласования** — вкладка «Согласования»: payload, сумма, контрагент, предупреждение
   «это не реальный платёж». Решение только OWNER (роль ADMIN получить 403 — это
   нормально). Одобрение черновика никогда не означает одобрение платежа.
4. **Результат процесса** — «принять / вернуть / отклонить» с причиной; возврат
   запускает переработку выбранных узлов.

## 4. Управление процессами (только OWNER)

Вкладка «Управление»: три тумблера (процесс / внешний LLM / инструменты записи) и
уровень автономности A0–A3. Действует немедленно, без изменения кода; каждое
изменение подписано. Остановка процесса = ручной режим: новые запуски паркуются,
выполняющиеся шаги завершаются безопасно. Возобновление — `POST /tasks/{id}/retry`
(продолжение с последнего checkpoint).

## 5. Что система никогда не делает

- Не выполняет банковский платёж и не подписывает документы.
- Не формирует финальный юридический вывод без подтверждённого источника.
- Не отвечает из памяти модели вместо КонсультантПлюс.
- Не подтверждает денежные действия без OWNER.
- Не показывает чужие данные другой компании (404 — это защита, а не ошибка).

## 6. Типовые ситуации

| Ситуация | Что это значит | Что делать |
|---|---|---|
| Задача в `waiting_source` | КонсультантПлюс недоступен/нет источника | Проверить канал; затем retry задачи |
| Задача в `failed_safe` | Исчерпаны повторы узла | Разобрать DLQ; retry продолжит с checkpoint |
| Задача в `waiting_approval` | Нужен OWNER (сумма выше лимита) | Согласование на вкладке «Согласования» |
| `action_denied` | Сработала stop-line (секрет, заблокированный контрагент, лимиты) | Причина — в policy_reasons результата |
| `stopped_by_switch` | Процесс остановлен kill switch | Включить во вкладке «Управление» |
