# Регрессионная оценка тестового поиска

```powershell
uv run python scripts/eval_retrieval.py --check
```

Команда создаёт отдельную in-memory SQLite и временное хранилище загрузок, затем удаляет их.
Она не использует рабочую БД, не отправляет документы внешним сервисам и не вызывает LLM.
JSON-отчёт выводится в stdout. Русские символы экранируются для совместимости с Windows-консолью.
Зависимости устанавливаются командой `uv sync --locked --dev`.

## Что измеряется

Набор `synthetic-retrieval-v1`: 10 документов legal_corpus.json плюс 2 русскоязычных примера
в retrieval_eval.json. Это заведомо синтетические тексты, не нормы права.

13 положительных запросов (включая запрос с двумя нужными источниками), 6 отрицательных:
отсутствующая тема, пунктуация, другая страна, прошлая дата, другой тип и другой владелец.
Статусы DRAFT/REVOKED/SUPERSEDED, классификации и границы дат дополнительно проверяются pytest.

Метрики на `top_k=3`:

- recall_at_k: средняя доля эталонных источников, найденных в выдаче положительных запросов;
- precision_returned: средняя доля релевантных среди фактически возвращённых источников,
  не precision@k с фиксированным знаменателем k;
- mrr_at_k: среднее обратного ранга первого релевантного источника;
- negative_empty_rate: доля отрицательных запросов с пустой выдачей.

Несколько чанков одного источника считаются одним источником. Пустая выдача по положительному
запросу получает нулевые recall/precision/MRR, а не искусственные 100%.
При `--check` любая метрика ниже 0.99 даёт код завершения 1. Проверка включена в CI.
`--top-k 1 --check` специально не проходит: запрос acceptance требует двух источников.

Локальный результат `mock-hash-lexical-v2`: все четыре метрики = 1.0 на этом наборе.
Это регрессия точных слов на маленьком известном корпусе, НЕ оценка юридической компетентности
и НЕ оценка поиска по смыслу. Нет независимого holdout, синонимов, морфологии, перевода,
сложных реальных документов, полноты законодательной базы или PostgreSQL benchmark.

## Изменение алгоритма

Модель векторов остаётся `mock-token-hash-v1-128`; миграция и переиндексация не нужны.
Версия retrieval изменилась на `mock-hash-lexical-v2`: перед top-k исключаются кандидаты,
у которых нет ни одного общего токена с запросом. Токенизация Unicode, регистр игнорируется.
Словоформы, синонимы и межъязыковые совпадения НЕ поддерживаются. Общие служебные слова
всё ещё могут дать нерелевантное совпадение, а настоящий семантический ответ — не найтись.

Отдельный тест строит два разных слова с одинаковым hash-вектором: ложный кандидат больше
не занимает место истинного ответа. Другой тест проверяет явную ошибку при превышении
5000 кандидатов, чтобы пилот не возвращал молча усечённый результат.

Старые сохранённые LegalResult без retrieval_version читаются как `mock-hash-v1`.
Новые результаты сохраняют актуальную версию, в том числе внутри agent runs.

Следующий шаг: выбрать semantic embedding provider и оценивать его на отдельном наборе
с перефразировками, отрицательными примерами и размеченными экспертами источниками.
