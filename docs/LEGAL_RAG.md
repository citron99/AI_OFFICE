# Legal KB: локальный тестовый инкремент

Опциональный semantic adapter и новая миграция 0004 описаны в [SEMANTIC_SEARCH.md](SEMANTIC_SEARCH.md).
Ниже описание mock-режима, если явно не указано иное.

Это пилот RAG, а не юридическая консультация. По умолчанию LLM в LawyerAgent не вызывается.
Сервер запускается только для локального пилота с синтетическими документами.
Аутентификации нет: API использует `usr_demo_owner`, production заблокирован.

## Legal Change Radar

`POST /api/v1/legal/change-radar/runs` сравнивает две зарегистрированные версии источника.
Запрос обязан передать `Idempotency-Key`, `baseline_source_id`, `current_source_id`, `subject`,
двухбуквенную `jurisdiction` и `effective_on`. Текущая версия должна быть ACTIVE и действовать
на указанную дату; историческая — ACTIVE, SUPERSEDED или EXPIRED. Оба источника проверяются по
`owner_id`, `company_id`, классификации и юрисдикции до загрузки текста.

Radar выполняет детерминированный diff индексированных фрагментов и сохраняет точные цитаты
обеих версий. Keyword-сигналы `high_attention/review/informational` служат только triage и не
являются юридической оценкой. Перед созданием результата обязателен успешный поиск метаданных
в разрешённом канале Консультант+; лицензированный полный текст не копируется. При недоступности
канала или отсутствии применимого источника обработка останавливается.

Результаты имеют статус `awaiting_legal_review` (либо `no_text_change`) и историю запуска.
Юрист или владелец фиксирует отдельное append-only решение через
`POST /api/v1/legal/change-radar/runs/{run_id}/review`. Повторная review запрещена. UI расположен
в разделе Legal RAG и показывает источники, даты, evidence trail и цитаты до/после.

## Сценарий

1. Применить `uv run alembic upgrade head` (новая миграция `20260827_0003`).
2. Загрузить UTF-8 TXT, текстовый PDF или DOCX через `POST /api/v1/files` (multipart `file`).
3. Зарегистрировать источник через `POST /api/v1/knowledge/sources`:

```json
{
  "artifact_id": "art_ID_ИЗ_ОТВЕТА_FILES",
  "title": "SYNTHETIC Contract",
  "jurisdiction": "LV",
  "document_type": "contract",
  "authority": "Synthetic fixture, not law",
  "version": "test-v1",
  "effective_from": "2026-01-01",
  "effective_to": null,
  "status": "ACTIVE",
  "classification": "INTERNAL",
  "language": "en"
}
```

По умолчанию источник имеет статус DRAFT и не участвует в поиске.
ACTIVE в этом локальном API задаётся оператором, а не реальным процессом согласования.
Повторная регистрация создаёт отдельный источник: дедупликация пока не реализована.
Вложение задачи само по себе не является источником права и не индексируется автоматически.

4. Выполнить `POST /api/v1/knowledge/search`:

```json
{
  "query": "contract payment acceptance",
  "jurisdiction": "LV",
  "effective_on": "2026-08-27",
  "document_types": ["contract"],
  "top_k": 5
}
```

В ответе: исходный текст фрагмента, source_id/chunk_id, название, версия,
authority, юрисдикция, интервал действия, локатор, статья и mock score.
Границы effective_from/effective_to включительные. Оба поля страны используют двухбуквенный
код в верхнем регистре; реестр юрисдикций и проверка применимости права пока отсутствуют.
Только ACTIVE: APPROVED, DRAFT, EXPIRED, REVOKED и SUPERSEDED не выдаются, даже для прошлой даты.
Архивный поиск по историческим статусам ещё не реализован.

5. Создать задачу `POST /api/v1/tasks`:

```json
{
  "message": "contract payment acceptance",
  "requested_agent": "lawyer",
  "jurisdiction": "LV",
  "effective_on": "2026-08-27"
}
```

Состояние completed означает окончание поиска, а не юридической проверки.
`result.status` — `retrieval_only` либо `legal_source_not_found`.
`evidence` содержит фрагменты, `citations` — ссылки на их локаторы; `findings` пуст.
Всегда рекомендуется проверка специалистом. Противоречивые источники не разрешаются автоматически.

Без страны или даты задача переходит в waiting_input. Продолжить ту же задачу:
`POST /api/v1/tasks/{task_id}/clarify` с телом
`{"jurisdiction":"LV","effective_on":"2026-08-27"}`. Повторное уточнение завершённой
или отменённой задачи возвращает 409. Полный диалоговый API ещё не реализован.

## Границы безопасности и качества

- SQL-фильтры владельца и классификации выполняются до загрузки фрагментов.
  Это минимальная owner-isolation, не полноценные production ACL/роли.
- PUBLIC также не даёт межпользовательский доступ. CONFIDENTIAL/RESTRICTED не выдаются.
- Сам поиск не отправляет документы внешнему провайдеру. Опциональный анализ отправляет
  ему запрос, отфильтрованные источники и извлечённые вложения. Инструкции внутри них — данные.
- `mock-token-hash-v1-128` детерминирован, но не семантичен. Поиск `mock-hash-lexical-v2`
  отбрасывает фрагменты без общих токенов с запросом, устраняя чисто hash-коллизии.
  Общие слова всё ещё могут давать нерелевантные результаты. Наличие совпадения не доказывает
  юридическую применимость или полноту поиска. Версия поиска возвращается в API и LegalResult.
  Смена модели требует переиндексации и согласованной миграции размерности.
- PostgreSQL: cosine-кандидаты через pgvector без ANN-индекса; SQLite: вычисление score в памяти.
  В обоих случаях lexical-фильтр применяется перед top-k. Пилот ограничен 5000 кандидатами
  после SQL-фильтров (в PostgreSQL дополнительно после порога cosine). Превышение возвращает
  ошибку, а не неполный успешный ответ; можно сузить document_types. Это не масштабируемый retrieval.
- PDF: максимум 200 страниц, без пароля; пустая/сканированная страница отклоняет весь документ.
  OCR отсутствует. Чтение PDF ещё не изолировано в процессе с CPU/memory limit.
- DOCX: основной текст и таблицы, номера абзацев. Физические страницы, примечания,
  колонтитулы, изображения и полная семантика редакторских изменений не поддержаны.
- Извлечённый текст ограничен 500 000 символами, индекс — 2000 чанками на документ.
  Разбиение длинной секции по символам — baseline, не полноценный юридический structure parser.
- Вложения задач извлекаются отдельно, проверяются владелец, классификация и SHA-256.
  До 10 вложений, суммарно до LEGAL_DOCUMENT_MAX_CHARS (по умолчанию 40 000 символов).
  Превышение лимита отклоняет обработку: договор не обрезается молча.
  Текст вложений участвует в дополнительных поисковых запросах, но не становится источником права.
  Вопрос и фрагменты вложений делятся по лимиту tokenizer локальной модели; максимум 64
  поисковых окна на задачу. Превышение отклоняет весь запрос до поиска. Полный текст
  вложений для анализа не заменяется окнами и не обрезается.
  При отключённом анализе возвращается `ATTACHMENT_ANALYSIS_DISABLED`.

## Проверка

`uv run pytest -q` проверяет изоляцию, временные границы, исключённые статусы,
метаданные, 10 синтетических источников, отсутствие источников, уточнение и сохранение цитат.
`uv run python scripts/smoke_local.py` запускает реальный HTTP-сервер на временной SQLite
после миграций. PostgreSQL проверен отдельным набором; live LLM не подтверждён.

`uv run python scripts/eval_retrieval.py --check` выполняет изолированную offline-регрессию
на 12 синтетических документах. Метрики и ограничения — [RETRIEVAL_EVAL.md](RETRIEVAL_EVAL.md).

## Опциональный анализ вложений (второй инкремент)

`LEGAL_ANALYSIS_ENABLED=false` по умолчанию. При `true` агент вызывает настроенный LLM
только после уточнения контекста, извлечения всех вложений и получения доступных источников.
Это opt-in на отправку извлечённого текста внешнему провайдеру, если выбран `anthropic`.
В этой реализации живые запросы не выполнялись; проверка сделана на подставном провайдере.
Обычный MockLLMProvider без заданного ответа не придумывает заключение: пустой ответ
отклоняется схемой. Рабочие offline-примеры — tests/integration/test_legal_analysis.py.

Промпты хранятся отдельно в app/prompts/legal.py: весь pipeline — `legal-grounded-v2`,
предварительная оценка — `legal-sufficiency-v1`.
LEGAL_ANALYSIS_TIMEOUT_SECONDS (по умолчанию 45 секунд) — общий бюджет двух вызовов.

Первый вызов возвращает оценку достаточности источников для всего запроса:
`sufficient`, `partial` или `insufficient`, объяснение, недостающие сведения и ссылки.
Для sufficient обязательны проверенные дословные цитаты источников и отсутствие
недостающих сведений. Вложение не может заменить источник права. Для остальных статусов
обязателен список недостающей информации. Противоречивые поля, неизвестные ID и неверные
цитаты отклоняются сервером. Только sufficient разрешает второй вызов — генерацию черновика.
При partial/insufficient возвращаются вопросы для уточнения, без генерации замечаний.

Оценка выполняется тем же настроенным провайдером, а не независимым экспертом.
Она может ошибиться даже с точными цитатами: это fail-closed проверка структуры/протокола,
не доказательство смысловой достаточности. Предупреждение SUFFICIENCY_MODEL_JUDGEMENT
сохраняется в результате. Retrieval API и его метрики не меняются; порог поиска не повышался.
В режиме без LLM оценка не выполняется.

Каждое замечание требует источник из текущей выдачи и точную цитату минимум из 8 символов.
Если приложен договор, дополнительно обязательны ID его фрагмента и дословная цитата.
Названия, версии и локаторы цитат берутся сервером из фактического контекста, не из LLM.
Любая неверная ссылка/цитата отклоняет весь ответ; частичный набор замечаний не публикуется.

Результат сохраняет `documents`, `verified_references`, `analysis_attempted`, `analysis_model`,
`evidence_assessment` и `evidence_assessment_version`. У старых результатов новые поля null.
verified_references относятся только к опубликованным замечаниям; ссылки предварительной
оценки хранятся отдельно. legal_sources_found означает наличие кандидатов, не достаточность.
Режим вызванного анализа — `legal_analysis_pilot`; старый retrieval-режим совместим.
Статусы:

- `draft_analysis`: черновик; дословность цитат проверена, юридическая логика — нет;
- `insufficient_evidence`: предварительная оценка отвергла полноту источников либо модель
  не вернула замечаний; это не одобрение договора;
- `analysis_rejected`: схема или цитаты не прошли проверку;
- `analysis_unavailable`: ошибка/тайм-аут, без публикации исключения провайдера;
- `legal_source_not_found`: LLM вообще не вызывался.

Состояние задачи completed означает окончание обработки, не юридическое одобрение.
Высокий/критический риск в замечаниях повышает risk_level задачи и требует проверки специалистом.
Approval API и блокировка конкретных бизнес-действий пока не реализованы.
Agent runs сохраняют модель и версию промпта; учёт токенов/стоимости по-прежнему не завершён.

Ограничения: проверка цитат не доказывает связь между цитатой и выводом. Противоречия
источников предлагается раскрывать в промпте, но отдельного алгоритма их обнаружения нет.
Prompt injection полностью не исключён. Полный текст извлечённых вложений хранится в результате
и agent run; до реальных документов нужны ACL, политика хранения и изолированный parser.
Настоящая модель и PostgreSQL проверены отдельно, но semantic quality gate не пройден:
[SEMANTIC_EVAL.md](SEMANTIC_EVAL.md). Остаются независимая оценка качества предварительной
проверки, live provider verification, OCR и production ACL. Живой LLM на этом этапе не вызывался.
